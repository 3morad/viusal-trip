Why the architecture looks like this

Spotify tells you what is playing, never what it sounds like.

Two separate doors closed in the same year, and between them they rule out every direct approach. Both are load bearing, so the design starts here rather than ending here.

Still available
  • Currently playing trackTitle, artist, album, duration and progress in milliseconds, polled from the player endpoint.
  • Album artworkFull resolution image URLs, which can be sampled for a per track palette seed.
  • Library and playlistsSaved tracks, playlists and search, enough to build a real browsing surface.
  • Playback controlPlay, pause, skip and seek against an active device, with the right scope granted.
Closed
  • Audio AnalysisBeat grid, bars, sections and per segment pitch and timbre vectors. Deprecated November 2024. New clients receive 403 and there is no replacement.
  • Audio FeaturesTempo, key, energy and danceability. Closed in the same deprecation, with quota extensions now gated behind 250k monthly users.
  • Playback audio samplesThe Web Playback SDK renders inside an iframe under Encrypted Media Extensions. An AnalyserNode cannot be attached to it, by design.
  • Thirty second previewsPreview URLs were pulled from new integrations through 2025, closing the last sanctioned route to raw audio.

Split the roles. Spotify names the track, the room supplies the sound.

Everything downstream of capture is identical whichever source is feeding it, so the file input is not a fallback bolted on later. It is the same pipe, and it is how the whole thing gets developed offline.

One consequence worth planning around. Speaker to microphone adds roughly 25ms of acoustic delay, and an 85ms analysis window sits on top of that. Reacting to an onset always lands late, so beat driven motion is scheduled against predicted phase rather than triggered on detection.

Chords become hue by walking the circle of fifths.

A twelve bin chroma vector falls out of the FFT almost for free. Fold every bin between C3 and C7 down to its pitch class, sum the linear magnitudes, and you have the harmonic content of the moment without knowing anything about the track.

Matching that vector against twenty four triad templates by cosine similarity gives the chord. Ordering the twelve pitch classes by fifths rather than by semitone means harmonically close chords land close in hue, so a ii V I drifts through neighbouring colour instead of strobing across the wheel.

A chord commits only once the same triad has kept winning for 180ms, held in seconds rather than frames so the feel does not change with frame rate. Passing tones and grace notes never reach the renderer.

What the pipeline actually hears.

Six bands, envelope followed

Raw bin energy is jittery and unusable. Each band runs through a follower with a 5ms attack and a 180ms release, then normalises against a rolling percentile so a quiet ambient record and a loud master both drive the full range.

Analysis window
85ms

4096 point FFT at 48kHz gives 2048 bins at 11.7Hz each. Fine enough for onsets and bands, too coarse for bass pitch, which is why chroma starts at C3.

Onset, tempo and phase

Half wave rectified spectral flux against a rolling median threshold gives onsets. Autocorrelating the flux over a six second window inside a 60 to 180 BPM lag range gives tempo, and aligning to the last strong onset gives a continuous phase value.

Phase is what the shaders want. A boolean beat flag arrives too late to be useful.

Harmonic and percussive split

Median filtering the spectrogram along time isolates sustained content, along frequency isolates transients. Seventeen frames of history is enough, and it runs comfortably in realtime.

This is the honest version of instrument separation. True stem splitting needs a network that will not run in a browser at 60fps, so melody and drums as two layers is where the line sits.

// The one contract between audio and render. Everything else is replaceable.
interface FeatureBus {
  bands:      Float32Array;  // 6, normalised 0..1, envelope followed
  chroma:     Float32Array;  // 12, pitch classes from C, unit max
  chord:      { root: number; quality: 'maj'|'min'|null; confidence: number };
  key:        { root: number; mode: 'maj'|'min' };  // 30s rolling estimate
  onset:      number;        // flux above threshold, decays over 120ms
  bpm:        number;
  beatPhase:  number;        // 0..1, continuous, predicted not reactive
  harmonic:   number;
  percussive: number;
  rms:        number;
  source:     'mic'|'file'|'synthetic';
}

Two layers of hand control, live at the same time.

Every continuous value is normalised against hand size before it leaves the tracker, so leaning toward the camera does not silently change the reading.

Smoothed with a One Euro filter rather than a lerp. Low lag when the hand moves fast, no visible jitter when it holds still.

A pose fires only once it has been held for 120ms, then locks out for 300ms. Both are wall clock, not frame counts. Transitional shapes between two deliberate gestures never trigger anything.

Three scenes, one bus, one renderer.

Each scene is a fragment shader reading the same uniform block. Adding a fourth means writing one file, not touching the pipeline.

A ping pong framebuffer warped, zoomed and rotated every frame so colour smears into itself. Cheapest of the three and the one that reads most immediately as a trip.

GPU cost: low

A bass reactive full screen flash is a seizure trigger, so the limiter is not optional.

The frame's mean luminance is read back from the smallest mip level every frame. If the delta between consecutive frames would exceed the safe threshold more than three times per second, the final pass clamps it. The scene keeps its motion and loses only the strobe.

Alongside that: an entry gate that states the risk plainly before anything goes fullscreen, a reduced intensity mode wired to the system preference, and a global ceiling on saturated red flashes, which are the worst offenders in the danger band.

Build order

Each step ends with something you can actually look at.

Capture

Vite and TypeScript, no framework. Both audio sources landing in one graph, with the three getUserMedia processing flags switched off, because echo cancellation and auto gain will quietly destroy the spectrum before you ever see it.

Ends with: a spectrum drawn to a canvas from either input.

Extract

The full DSP chain and the feature bus behind it. Bands, chroma, chord matching, flux, tempo, phase and the harmonic split, plus a debug overlay showing every value at once so the tuning work has something to argue with.

Ends with: chord names appearing over a track you know.

Render

WebGL2, the ping pong feedback buffer, the shared uniform block, the post chain and the flash limiter. One scene only. This is where the project either feels good or does not, so it gets the tuning time.

Ends with: the first scene reacting properly to real music.

Reach

MediaPipe HandLandmarker with self hosted WASM, the One Euro filter, the continuous mappings and the pose recogniser. Tracking runs on its own 30fps budget so it never competes with the render loop for frames.

Ends with: hands driving the scene with no visible lag.

Connect

Spotify PKCE, now playing polling with locally extrapolated progress, artwork palette extraction, and the remaining two scenes. Worth doing last precisely because it is the part most likely to change under you.

Ends with: track name, art and palette live on screen.

What is most likely to go wrong.

Loopback setup friction

A room mic works but picks up conversation, and a clean signal needs a virtual audio device the user has to install and route themselves.

Budget real time for a per platform setup guide with a live input meter, and make the file input genuinely good so nobody is forced through it to try the thing.

Two GPU consumers, one GPU

Hand tracking and a raymarched fractal both want the graphics card. On integrated hardware they will fight and the frame rate collapses.

Run the tracker in a worker against an OffscreenCanvas at a fixed 30fps, and drop the render resolution before dropping the frame rate.

Spotify moving again

An API that removed four endpoint families in eighteen months can remove more, and development mode caps you at 25 manually added users.

Keep everything Spotify touches behind one adapter with a null implementation. If the account is not connected, the visualizer still runs, it just stops knowing the track name.
